CiteLoom turns mixed document collections into searchable evidence and cited answers.
Workspaces, shared source libraries, retrieval settings, and model routes let one installation serve different knowledge domains while keeping authorization.

![A CiteLoom feature map shows the document library, Ask, Chat, Search, MCP, indexing, storage, access, and speech features.](/citeloom/images/citeloom-feature-map-v2.png)

## Put each model where it belongs

<CardGrid>
  <Card title="Local models" icon="seti:lock">
    Keep inference on infrastructure you control when document privacy, predictable data residency, or offline operation matters most.
    CiteLoom supports local endpoints such as Ollama and other compatible services.
  </Card>
  <Card title="Remote providers" icon="seti:cloud">
    Use managed models when you need broader model choice, elastic capacity, or a capability your local hardware does not provide.
    CiteLoom sends content only to the provider routes you configure for each feature.
  </Card>
  <Card title="A deliberate mix" icon="seti:settings">
    Keep embeddings and document processing local while routing answer generation, ranking, speech, or visual document work to selected remote providers.
    Each feature has its own route, model, limits, and credentials.
  </Card>
</CardGrid>

## Why use CiteLoom

<CardGrid>
  <Card title="Answers stay tied to evidence" icon="document">
    Ask and Chat preserve citations to the exact source versions used for a saved answer.
    You can inspect cited text, tables, images, and highlighted source passages.
  </Card>
  <Card title="Search is useful without generation" icon="magnifier">
    Find exact keyword matches or related material without asking a language model to write an answer.
    Retrieval can be keyword, semantic, or hybrid.
  </Card>
  <Card title="Infrastructure is composable" icon="setting">
    The base Compose stack works on its own.
    Add S3-compatible object storage or a compatible authorization server only when the deployment needs them.
  </Card>
  <Card title="MCP is built in" icon="puzzle">
    Connect interactive clients through OAuth or unattended clients through a revocable, user-bound API key with explicit workspace selection.
    Both methods use the same CiteLoom authorization and retrieval services.
  </Card>
</CardGrid>
